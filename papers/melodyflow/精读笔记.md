## 基本情况

- 一句话：输入一段真实或生成的音乐和编辑文字，输出在改变指定属性后仍尽量保留原曲结构的高保真立体声音频；也能从文字直接生成音乐。
- 开源范围：公开的是 AudioCraft/MelodyFlow 推理与 demo 代码及预训练权重；训练代码未公开。专用实现位于 [facebook/MelodyFlow Hugging Face Space](https://huggingface.co/spaces/facebook/MelodyFlow)，不应误认为当前 AudioCraft GitHub 默认分支含有同一套独立 MelodyFlow 文件。代码 MIT；权重 CC-BY-NC 4.0（模型卡）。
- 和后续论文的关系：它先解决“音乐如何压成适合连续 flow 建模的 latent，并通过反演编辑”；后面的 FlowEdit 等工作针对直接编辑是否能绕开反演。

## ① 动机

### 先用一句话说它做什么

给模型一段现成音乐和一句修改要求，例如“把合成器低音改成 oud（乌德琴）低音，保留怀旧、充满活力的感觉”，模型需要改动音色与风格，同时尽量不毁掉原有节奏、旋律走向和整体情绪。MelodyFlow 让同一个模型也能从文字生成音乐；编辑时则把已有音乐先映到连续 latent，再沿生成模型学到的 ODE 路径反向走一段、换编辑文字向前生成。

### 以前卡在哪里

1. **专用编辑模型只会少数操作。** 过去常见方案各自处理人声移除、补全或旋律条件等特定任务，不容易把同一个编辑器用于换乐器、换流派、改录音环境等开放式要求。
2. **高保真立体声让离散 token 很贵。** 48 kHz 双声道波形本身很长。若用离散 codec，想保住细节通常要提高 token 帧率、词表或残差码本数量，生成模型也随之变重、变慢。
3. **只从噪声重新生成，原曲容易丢。** 文字生成模型知道目标风格，却没有原曲的具体节拍、配器和旋律；必须找到一条从原曲通往可编辑状态的路径，才能在改目标时留下足够多原有信息。
4. **朴素反演不够可逆。** Flow Matching 理论上用直线路径连接噪声与数据，但训练出的速度场和实际求解轨迹不会完全笔直；分类器自由引导还会让速度预测偏离训练分布。简单地把 ODE 倒着积分再正着积分，重建可能漂移，编辑也可能顾此失彼。

### 作者押注的关键想法

作者押注：如果先用低帧率、量化自由的连续 VAE codec 把 48 kHz 立体声压成平滑 latent，再让一个文本条件 DiT 学会从噪声到音乐 latent 的流，那么生成可以用较少 ODE 步完成；对真实音乐做编辑时，再把 ReNoise 的逐步校正思想改造成 flow 版本，反向轨迹会更适合编辑和重建。

### 具体场景

原曲描述是“怀旧、反思的电子另类音乐，带有充满活力的合成器低音”。编辑提示改成“怀旧、反思的中东另类音乐，带有 oud 低音，依然充满活力”。模型的目标不是重新写一首完全无关的中东音乐，而是把低音音色与风格往 oud / 中东方向推，同时保留原有音乐的活力和可辨认的组织。作者项目页列出了这类源描述和编辑提示的试听对照。

### 图 1 先看什么

[打开论文 PDF 第 3 页的图 1](https://arxiv.org/pdf/2407.03648#page=3)。图展示的是完整编辑闭环：真实波形先经 VAE 编码；上半部分用 DiT 和 ODE 反向估计中间 latent，并逐步做 regularization；到达编辑时间点后，下半部分换成目标文字，正向积分生成编辑后的 latent，最后由 VAE 解码回波形。接下来架构站会逐块拆图；本阶段先抓住动机：编辑器要有一条既能从原曲出发、又能朝新文字条件前进的连续路径。

**一句话回顾：** MelodyFlow 用低帧率连续音频 latent 降低高保真立体声生成成本，再用经正则化的反向 ODE 轨迹给零样本音乐编辑保留原曲依据。

**来源校准：** 上述问题动机与方法主张来自论文 §1–2；具体 oud 编辑场景来自作者项目页示例。论文实验结论和“现在的研究地位”留到第⑦站再讨论。


## ② 架构：连续 latent 上的文本条件流

### 先把图 1 读成一条管线

输入波形 → VAE codec 编成连续序列 (x_{src}) → 以源描述（或空文本）条件反向求解 ODE，得到中间态 (z_{T_{edit}}) → 以编辑提示为条件从 (T_{edit}) 正向求解 ODE → codec 解码成编辑波形。图中上半段负责“把原曲搬到可编辑位置”，下半段负责“带着原曲信息朝新文本生成”。[论文图 1（PDF 第 3 页）](https://arxiv.org/pdf/2407.03648#page=3)

### 三块核心组件

**1. 连续音频表示。** 论文 §2.1 的 codec 从 EnCodec 衍生，并吸收 DAC 的 Snake 激活和分频带 STFT 判别器，以及 KL 正则化瓶颈和感知加权。卷积 VAE 把高采样率波形压成低帧率连续 latent；medium 模型处理 48 kHz 立体声、25 帧/秒。它没有先把 latent 量化为离散 codebook token，因此后续 DiT 在连续向量序列上工作。

**2. 文本条件 Flow Matching DiT。** 训练时取音乐 latent (x) 和高斯噪声 ε，按
[
z_t=t x+(1-t)\epsilon,\qquad t\in[0,1]
]
构造中间态。线性路径的目标速度是
[
\frac{dz_t}{dt}=x-\epsilon=v_\theta(z_t,t,c).
]
DiT 接收当前 latent、flow 时间 (t) 和文本条件 (c)，用 T5 文本表征做 cross-attention，估计速度向量场。生成时从 (z_0=\epsilon) 开始，把这个场交给 ODE 求解器从 (t=0) 积到 (1)，得到 (z_1\approx x)，再经 VAE decoder 还原波形。

**3. 正则化反演编辑。** 对原曲编码得到 (x_{src}) 后，从 (t=1) 反向积分到 (T_{edit})，得到 (z_{T_{edit}})。再换目标文字 (c_{edit})，从 (T_{edit}) 向 (1) 积分。理想情况下，若目标文字仍是源描述，正向重建应近似还原输入；真实速度场受数值误差和 CFG 影响会漂移，因此作者逐步修正反演轨迹，并用 patch-KL 项约束预测速度的统计特征（§2.3–2.4）。

### 用小例子理解时间方向

设原曲 latent 是 (x_{src})，其描述是“轻快的合成器流行乐”，编辑提示是“轻快的合成器流行乐，加入木吉他”。先从 (t=1) 的原曲 latent 反向积分到 (T_{edit}=0.04)，过程中仍用源描述并做可逆性校正；随后在这个中间 latent 上改用新提示，正向走回 (t=1)。因为起点来自原曲而非纯噪声，模型有机会保留节奏、段落组织和主旋律走向，同时把音色推向木吉他。保留多少是连续权衡，不是逐轨隔离，因此不能保证只改一个乐器。

### 论文设置与代码默认值要分开读

论文 medium 模型报告 25 次反向步、每步 (K=4) 次可逆性估计、λKL=0.2；编辑 CFG 取 4.0。公开 wrapper 的默认编辑参数是 Euler 25 步、regularization 开启、4 次迭代、最后保留 2 次迭代、λ=0.2，默认 (T_{edit}=0.0)。因此复现实验应显式传入论文设置（论文主实验的 (T_{edit}) 与代码 API 默认值不同），不能仅依赖默认参数。细节见[代码树与论文对照](./代码树与论文对照.md)。

### 结构回顾

`MelodyFlow` wrapper 串接 codec 与连续 flow 模型；`FlowModel` 承担 DiT 速度预测、文本条件、CFG、ODE 正反向积分和反演正则化；codec 负责编解码。源码里变量名 `lm` 容易误导：此处核心生成器仍是连续 latent FlowModel，并非离散 token 的自回归语言模型。每个目录和论文小节的逐项映射见独立代码树说明。

**本阶段一句话：** MelodyFlow 把高保真音乐编辑变成“连续 latent 中的可条件 ODE 轨迹搬运”，反演端把原曲信息带到中间态，生成端再沿目标文本速度场前进。
