## 基本情况

- **任务：** 使用预训练文本到图像 flow 模型，对真实图像做文本条件编辑。本文研究的是图像编辑；它与 MelodyFlow 的音乐编辑应用相邻，但输入、表征和评测任务不同。
- **一句话：** 不把源图先反演成高斯噪声，再从噪声生成目标图；而是构造一个直接把源提示条件分布运向目标提示条件分布的 ODE，并在每一步相减源/目标速度场。
- **核心主张：** 免反演、免测试时优化、对模型架构相对无关；比“反演再生成”路径具有较低传输代价，从而改善源图结构保留。论文以 Stable Diffusion 3 和 FLUX 展示结果。
- **开源：** 有官方 PyTorch 仓库 [fallenshock/FlowEdit](https://github.com/fallenshock/FlowEdit)，MIT 许可；后续精读将把代码目录与论文方法逐项对照。
- **视觉导读：** [项目页 overview](https://matankleiner.github.io/flowedit/) 展示反演路径、由源/目标速度差导出的直接路径，以及 FlowEdit 的噪声采样路径；[论文首页图 1](https://openaccess.thecvf.com/content/ICCV2025/papers/Kulikov_FlowEdit_Inversion-Free_Text-Based_Editing_Using_Pre-Trained_Flow_Models_ICCV_2025_paper.pdf) 展示真实图像编辑样例，例如招牌文字修改、猫变浣熊、山变火山。
- **先记住的界限：** 作者声称的是相对于 inversion-based editing 更短、结构保持更好的映射，不是严格求得数学上的最优传输；强结构保持也可能限制大幅度修改。

## ① 动机：绕过“先去噪再重画”

### 先从编辑目标想起

给定一张有猫的照片和源描述“a cat sitting on a sofa”，希望生成“a raccoon sitting on a sofa”。理想编辑只改变动物身份，仍保留沙发、姿势、构图、光照和背景。传统的生成模型知道怎样按目标文字画浣熊，却不知道原图里哪些像素/结构应当留下。

### 反演范式的路径问题

常见做法先用源提示把输入图沿 flow 反向追到噪声，再用目标提示从该噪声走回来。理想数学流若能精确逆转，源图可以重建；但实际数值积分、CFG 和模型速度场误差会使噪声点偏离真实的源图轨迹，重生成时细节就可能改掉。即使拿到精确反演点，绕过高斯噪声再回来的路径也可能让源图的不同语义模式被错误配对，改变超过编辑需求的内容。

注意这不仅是“反演误差”问题。作者用合成多峰分布说明：source→Gaussian→target 的往返诱导出的源/目标配对可能交叉，成本较高；真实图像里表现为目标对象虽变了，但背景或构图也漂移。许多旧方法再注入注意力图或做内部优化来补偿，往往依赖特定架构，不容易迁移到 FLUX、SD3 等 flow 模型。

### 作者的转向

既然编辑最终要把源分布变成目标分布，作者问：能否直接建一条 source-to-target 的连续路径，而不必穿过标准高斯空间？FlowEdit 在同一时刻分别查询源提示与目标提示的 flow 速度，用二者差作为编辑方向；每一步为源样本加共享噪声，构造目标侧对应状态，然后沿速度差 ODE 推进。这样把“保留源中与编辑无关的内容”写进源/目标速度的相对变化中。

### 看图时抓重点

[论文图 1](https://openaccess.thecvf.com/content/ICCV2025/papers/Kulikov_FlowEdit_Inversion-Free_Text-Based_Editing_Using_Pre-Trained_Flow_Models_ICCV_2025_paper.pdf) 的例子包括把招牌上的 “LOVE” 改成 “FLOW”、猫改为浣熊、山改为火山。图中强调保留背景和构图，不代表每个编辑只影响一个对象。后续架构站会精确拆解速度差方程，并说明“直接路径”为什么仍采样噪声。

**一句话回顾：** FlowEdit 的出发点是，编辑不必先把源图送到噪声端再回来；可以直接沿源条件和目标条件速度场的差异，从源分布运到目标分布，减少无关结构改动。

**来源校准：** ICCV 2025 官方页面给出发表信息与摘要；论文图 1、§1、§3 解释任务和方法动机；项目页提供可视路径说明；官方 GitHub 证实代码仓库和 MIT 许可。结构保留、较低传输成本属于作者报告的主张，实验证据与限制留在第⑦站。


## ② 架构：噪声配对与速度差 ODE

### 1. 先把反演改写成直接路径

设源提示条件下的 latent 为 (Z_t^{src})，目标提示条件下为 (Z_t^{tar})，预训练 flow 的速度分别为 (V_t^{src})、(V_t^{tar})。传统 editing-by-inversion 先把源样本送到共同噪声，再由目标条件送回。作者指出，这条过程可以重新写成 source→target 的直接路径 (Z_t^{inv})，其速度正好是两种条件速度的差：
[
dZ_t^{inv} = (V_t^{tar}(Z_t^{tar},t)-V_t^{src}(Z_t^{src},t))dt
=V_t^\Delta dt.
]
它不再显式输出噪声图，但配对方式仍沿用原反演路径，因此合成多峰分布里仍可能把模式交叉配错。这是“取消 inversion”与“得到更好的直接映射”之间的关键区别。

### 2. FlowEdit 把确定性反演配对换成随机噪声配对

FlowEdit 保留相同速度差 ODE，却用随机过程 (hat Z_t^{src}=(1-t)X^{src}+tN_t) 产生源侧状态（(N_t) 为高斯噪声），并平移出对应的目标侧状态：
[
hat Z_t^{tar}=Z_t^{FE}+hat Z_t^{src}-X^{src}.
]
同一个噪声 (N_t) 同时加到源、目标两侧，所以两者共享噪声成分；相减速度时，共同噪声方向大体抵消，剩下更接近“把目标内容加到当前编辑状态上”的变化方向。每一步计算 (V_t^{tar}(hat Z_t^{tar},t)-V_t^{src}(hat Z_t^{src},t))，对 (n_{avg}) 个噪声配对求平均，再沿 ODE 更新 (Z_t^{FE})。

### 3. 一步更新具体在做什么

时间从 (t=1)（源图）向 (t=0)（目标分布）递减。每步先用当前共享噪声分别查询源提示和目标提示速度，算出速度差，再乘以负的时间步长更新编辑 latent。它不像标准生成那样每一步只查目标速度：源速度提供“若仍服从源描述，此处会往哪走”的参照；相减后留下由目标描述额外要求的变化。

这可以解释论文所说的噪声由粗到细：(t) 大时共同噪声强，速度差更多反映粗粒度语义；随着 (t) 下降、噪声减弱，速度差逐渐反映纹理等细节。共享噪声是耦合工具，不是最终编辑图像额外带噪。

### 4. 两个控制量：编辑强度与风格自由度

- `n_max`：跳过最早的高噪声时间段，越小意味着更少编辑更新，倾向保留更多源结构；越大则路径走得更完整、编辑更强。
- `n_min`：可把末端若干步交给常规目标条件采样，减少源图约束、放开整体风格变化。默认 0 时全程使用速度差更新。
- `n_avg`：每一时间步平均多少组噪声配对；增大通常更平滑、结构保持更稳，但计算量近似线性上升。默认通常为 1。
- 源和目标 CFG 可分别设置；提示的源/目标强弱因此能独立调节。

### 5. 论文方法与实现对应

官方 [`FlowEdit_utils.py`](https://github.com/fallenshock/FlowEdit/blob/main/FlowEdit_utils.py) 中，`FlowEditSD3` / `FlowEditFLUX` 初始化 `zt_edit=x_src.clone()`；循环中抽取 `fwd_noise`，形成 `zt_src=(1-t_i)*x_src+t_i*fwd_noise` 与 `zt_tar=zt_edit+zt_src-x_src`；再调用模型得到两种速度并累加 `(Vt_tar-Vt_src)/n_avg`，最后作显式 Euler 更新 `zt_edit += (t_{i+1}-t_i)*V_delta_avg`。这个短代码段就是论文算法的执行骨架。

在 SD3/FLUX 路径中，CFG 的条件和无条件 batch 也会一并计算；模型架构适配集中在 transformer 调用和 latent packing，而核心差速度更新一致。工程代码按模型维护两个 sampler，所谓 model-agnostic 指核心操作不要求修改模型权重/训练结构，并非不需要适配不同 pipeline 的输入输出接口。

### 本阶段一句话

FlowEdit 不是“把源 latent 直接复制进目标生成”，而是用共享噪声构造可比较的源/目标中间状态，并沿两者速度之差把编辑态从源端推向目标端。它改变的不只是有没有反演步骤，也改变了每个源样本与目标分布的耦合方式。

## ③ 训练：训练自由的测试时编辑

FlowEdit 不引入可训练参数，也不微调 SD3 或 FLUX。训练工作发生在底座文本到图像 flow 模型此前的预训练阶段；编辑时，模型权重冻结，只反复前向计算两个条件的 velocity，并把其差用于积分。论文称它同时 inversion-free、optimization-free：不求源图的 noise code，也不通过反向传播优化 latent。

### 一次编辑为什么仍然耗算力

“免训练”不等于“零成本”。每一个活动时间步都要估计 source velocity 与 target velocity；若 `n_avg>1`，每步还会对多组独立噪声重复计算，然后平均速度差。SD3 的 CFG 会把源/目标及其 unconditional/text 两路条件合并成一组 transformer batch；因此脚本能减少单独调用开销，但每一步仍需要模型预测。更多 (n_{avg})、步数和高 CFG 都会增加显存或推理时间。

### 训练时没有的参数，编辑时却有的旋钮

编辑没有学习新权重；主要选择包括 ODE 步数 (T)、`n_max`、`n_min`、噪声配对平均数 `n_avg)、source/target guidance scale 和 seed。它们改变速度场组合、积分范围和随机配对，而不改变底座模型本身。论文按 SD3 和 FLUX 分别调参，因此可迁移的核心公式并不意味着“一套数值配置直接通用”。

### 一个类比

把预训练模型看作已经学好“在给定文本下，当前图像 latent 下一步往哪走”的导航器。FlowEdit 不重新训练导航器；每一步同时问“源描述会把它往哪带？”和“目标描述会把它往哪带？”，从两条回答中减去源方向，再沿剩下的差值推进。这个类比对应算法，不代表两张编辑图相减或像素级蒙版操作。

**本阶段一句话：** FlowEdit 是固定底座模型上的测试时 ODE 控制方法，不需训练或梯度优化；其推理预算由时间步、两套条件速度预测和噪声平均决定。
