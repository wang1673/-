## 逐项对应论文

| 论文部分 / 数学对象 | 官方实现 | 实际作用 |
|---|---|---|
| §3 将 inversion 写为 source-target 直接 ODE | `FlowEditSD3`、`FlowEditFLUX` | 定义源、目标 prompt，各自取得 velocity；以 (V^{tar}-V^{src}) 推动编辑状态。 |
| §5 随机源侧路径 (hat Z_t^{src}) | `FlowEdit_utils.py` 中 `fwd_noise`、`zt_src` | 每个步长采高斯噪声，线性混合源 latent 与噪声。 |
| 目标侧平移关系 (hat Z_t^{tar}=Z_t^{FE}+hat Z_t^{src}-X^{src}) | `zt_tar = zt_edit + zt_src - x_src` | 让两边沿用同一噪声成分；速度差中抵消共同噪声趋势。 |
| 条件速度预测 / CFG | `calc_v_sd3`、`calc_v_flux` | 在模型 pipeline 上调用 transformer；SD3 与 FLUX 输入接口不同，因此有分支适配。 |
| 随机速度估计平均 | `V_delta_avg` 循环、`n_avg` | 平均多组噪声下的速度差；减少配对随机性，增加前向计算量。 |
| FlowEdit ODE 数值积分 | `zt_edit += (t_{i+1}-t_i) * V_delta_avg` | Euler 一步更新；时序从高噪声到低噪声递减。 |
| 控制编辑区间/自由度 | `n_max`、`n_min` | `n_max` 控制跳过多少起始高噪步；`n_min>0` 时末段转常规目标条件采样。 |
| SD3 / FLUX 实验细节 | `SD3_exp.yaml`、`FLUX_exp.yaml` | 持有 model type、ODE 步数、两套 CFG、平均数、区间参数和 seed。 |
| 表格/定性样例运行入口 | `run_script.py` + `edits.yaml` | 加载模型及实验配置，遍历编辑样本，调用相应 sampler 并落盘结果。 |

## 一次编辑的调用链

1. `run_script.py` 解析 `--exp_yaml`，按 `model_type` 加载 Diffusers 的 `StableDiffusion3Pipeline` 或 `FluxPipeline`。
2. 从 `edits.yaml` 读取图像、source prompt、target prompt；载入图片后按对应 pipeline 编码为 latent。
3. 调用 `FlowEditSD3` 或 `FlowEditFLUX`，分别编码 source/target 文字条件，建立离散 scheduler 时间表。
4. 从 (t=1) 方向开始编辑积分。每个活动步采 (n_{avg}) 组噪声；对每组噪声构造共享噪声 source/target latent，预测速度差并取均值。
5. 乘时间差用 Euler 推进编辑 latent。若设置 `n_min>0`，末尾部分改成纯 target prompt 采样。
6. pipeline VAE 将最终 latent 解码回图像，由运行脚本保存和记录。

## 阅读源码时要留心

- **这里的 velocity 是 Diffusers flow scheduler / transformer 返回的模型速度张量。** 代码变量有时命名为 `noise_pred`，不要仅凭变量名就把它当成标准 DDPM 的 epsilon。
- **核心公式跨 SD3 与 FLUX 共用，接口逻辑不共用。** Transformer 入参、prompt encoding、guidance embedding 和 latent packing 各自适配两种架构。
- **`n_max` 和 `n_min` 的实际循环判定要看 (T_steps-i)。** 参数增减的直觉应结合论文时间方向以及配置一起理解。
- **论文声称低 transport cost，不等于严格 OT。** 论文明确说其启发式不保证精确到目标分布，也不保证最优传输；这是方法边界。
- **默认参数并非不同模型相同。** 仓库 FLUX YAML 为 28 步、source/target CFG=1.5/5.5、n_max=24；SD3 配置与界面默认另有设置，不能把一组默认值推广到全部模型。
